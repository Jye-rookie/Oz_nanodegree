# 당뇨 환자 30일 내 재입원 케이스 탐색기: 재현 프롬프트

아래 "프롬프트" 블록을 Claude Code에 그대로 붙여넣으면 같은 대시보드를 다시 만들 수 있습니다. 앞뒤 설명은 사람이 읽는 용도입니다.

## 결과물 한눈에 보기

- 산출물: 데이터가 내장된 단일 HTML 파일 1개 (약 6.8MB, 외부 데이터 요청 없음)
- 데이터: UCI "Diabetes 130-US Hospitals for Years 1999–2008" (입원 101,766건, 환자 71,518명, 비식별 공개 데이터)
- 사용자: 임상연구자(후향적 분석)
- 핵심 질문: 어떤 입원이 30일 안에 재입원으로 이어지는가 (재입원 위험요인)
- 디자인: MongoDB LeafyGreen 디자인 시스템(https://www.mongodb.design)의 Palette·Typography 기준

## 프롬프트

```text
당뇨 환자의 30일 내 재입원 위험요인을 임상연구자가 후향적으로 탐색하는 인터랙티브 대시보드를 단일 HTML 파일로 만들어줘.

[1. 데이터]
- 출처: UCI Machine Learning Repository, "Diabetes 130-US Hospitals for Years 1999-2008"
  https://archive.ics.uci.edu/static/public/296/diabetes+130-us+hospitals+for+years+1999-2008.zip
- zip 안의 diabetic_data.csv(101,766행, 50개 컬럼)와 IDS_mapping.csv를 사용한다.
- 파일은 별도 빈 폴더에 내려받아 풀고, 내려받기 전에 출처와 파일명을 사용자에게 알린다.
- 데이터 내용을 먼저 확인한다: readmitted 분포, 결측 비율(weight 97%, payer_code 40%, medical_specialty 49%, A1Cresult의 None 83%, max_glu_serum의 None 95%).
- weight, payer_code, medical_specialty, max_glu_serum은 결측이 많아 대시보드에서 쓰지 않는다.

[2. 분석 기준 (사용자와 합의한 값)]
- 재입원 = readmitted == "<30" 만. ">30"은 재입원으로 보지 않고 "30일 초과"로 따로 표시한다.
- 사망·호스피스 퇴원(discharge_disposition_id 11, 13, 14, 19, 20, 21)은 기본으로 분석에 포함한다.
  이 입원은 재입원이 불가능해 재입원률을 낮추므로, 화면에 건수를 안내하고 "사망·호스피스 퇴원 제외" 토글을 제공한다.
- 단위는 입원(encounter)이다. 환자 수는 patient_nbr의 고유 개수다.
- 같은 환자의 입원 순서는 encounter_id 오름차순을 시간 순서로 간주한다(원본에 날짜가 없음). 이 가정을 화면 하단에 밝힌다.
- 위험요인은 이전 이용 이력과 치료·검사 두 묶음으로 한정한다. 인구통계(연령, 성별)는 필터와 케이스 정보로만 쓰고 위험요인 차트에는 넣지 않는다.

[3. 전처리 (Python으로 컬럼 단위 JSON을 만들어 HTML에 내장)]
컬럼 배열(JSON) 형태로 저장한다: enc, pt, age, sex, race, adm, src, dis, los, labs, proc, meds, nout, nemr, ninp, dg, ndx, a1c, ins, chg, dmed, rd, icd

- enc = encounter_id, pt = patient_nbr
- age: 구간 인덱스 0~9 ([0-10) ... [90-100))
- sex: Female 0, Male 1, 그 외 2
- race: Caucasian 0, AfricanAmerican 1, Hispanic 2, Asian 3, Other 4, "?" 5(미상)
- adm (admission_type_id): 1 -> 0(응급), 2 -> 1(긴급), 3 -> 2(선택), 나머지 -> 3(기타)
- src (admission_source_id): 1·2·3 -> 0(의뢰), 4·5·6 -> 1(타시설 전원), 7 -> 2(응급실), 나머지 -> 3(기타)
- dis (discharge_disposition_id):
  1 -> 0 자택
  6·8 -> 1 자택+방문서비스
  3·4·22·23·24 -> 2 요양·재활시설
  2·5·9·10·12·15·16·17·27·28·29·30 -> 3 타병원·기관 전원
  11·13·14·19·20·21 -> 4 사망·호스피스
  그 외(18, 25, 26, 7 등) -> 5 기타
- los = time_in_hospital, labs = num_lab_procedures, proc = num_procedures, meds = num_medications
- nout = number_outpatient, nemr = number_emergency, ninp = number_inpatient (직전 1년 기준)
- ndx = number_diagnoses
- a1c: None 0(미검사), Norm 1, ">7" 2, ">8" 3
- ins (insulin): No 0, Steady 1, Down 2, Up 3
- chg: change == "Ch" 이면 1, 아니면 0
- dmed: diabetesMed == "Yes" 이면 1
- rd (readmitted): NO 0, ">30" 1, "<30" 2
- icd = diag_1 원문 문자열
- dg: diag_1(ICD-9)을 질환군으로 묶는다.
  V 또는 E로 시작하거나 결측 -> 8(기타)
  250.xx -> 4(당뇨병)
  390–459, 785 -> 0(순환기계)
  460–519, 786 -> 1(호흡기계)
  520–579, 787 -> 2(소화기계)
  800–999 -> 3(손상·중독)
  710–739 -> 5(근골격계)
  580–629, 788 -> 6(비뇨생식계)
  140–239 -> 7(신생물)
  그 외 -> 8(기타)
  질환군 이름: 순환기계, 호흡기계, 소화기계, 손상·중독, 당뇨병, 근골격계, 비뇨생식계, 신생물, 기타

[4. 대시보드 구성 (위에서 아래 순서)]
1) 헤더: 제목 "당뇨 환자 30일 내 재입원 케이스 탐색기" + 데이터 출처 한 줄 설명
2) 필터(칩 다중 선택, 선택 없음 = 전체):
   연령대(10년 단위), 성별, 입원 유형, 퇴원처, 주진단 질환군,
   옵션: "사망·호스피스 퇴원 제외" 토글, "필터 초기화" 버튼
3) KPI 5개: 30일 내 재입원률(가장 크게, 95% 신뢰구간과 전체 평균 병기), 입원 건수, 재입원 건수, 환자 수, 평균 입원일수
4) 안내 문구: 선택 조건의 사망·호스피스 건수 또는 표본이 300건 미만일 때의 주의 문구
5) 위험요인 가로 막대 묶음. 각 막대는 해당 구간의 재입원률, 건수, 선택 조건 평균을 나타내는 세로선을 가진다.
   - 이전 이용 이력: 최근 1년 입원 횟수(0/1/2/3+), 응급실 방문(0/1/2+), 외래 방문(0/1/2+)
   - 치료·검사: 입원일수(1–3 / 4–7 / 8+), 투약 수(≤10 / 11–20 / 21+), 검사 수(<30 / 30–49 / 50+),
     시술 수(0/1/2+), HbA1c(미검사/정상/>7/>8), 인슐린(미사용/유지/감량/증량),
     약물 변경(없음/변경), 진단 수(≤5 / 6–8 / 9+)
   - 진단·퇴원 비교: 주진단 질환군, 퇴원처, 입원 경로
6) 히트맵: 이전 입원 횟수(행 4개) x 입원일수(열 3개)별 재입원률. 건수 30 미만 셀은 흐리게 처리한다.
7) 케이스 목록(상위 40건, 정렬 선택: 이전 입원 횟수/입원일수/투약 수/응급실 방문, "30일 내 재입원 케이스만" 토글)과
   상세 패널(행 클릭 또는 키보드 Enter): 환자 속성, 진단, 치료·검사 정보, 같은 환자의 다른 입원 기록 표
8) 하단 주석: 재입원 정의, 사망·호스피스 처리, 결측 안내, "연관성이지 인과가 아님", encounter_id 순서 가정

[5. 해석 보조 규칙]
- 재입원률 = 재입원 건수 / 입원 건수
- 95% 신뢰구간은 Wilson 방식으로 계산해 막대 툴팁에 표시한다.
- 툴팁 내용: 재입원률, 신뢰구간, 재입원 건수 / 전체 건수, 선택 평균 대비 배수
- 건수 100 미만 막대는 흐린 색과 "건수가 적어 해석 주의" 문구를 쓴다.
- 평균의 1.2배 이상이면서 건수 100 이상인 막대는 경고색(빨강)으로 표시한다. 나머지는 기본 데이터색(파랑)이다.
- 모든 집계는 현재 필터를 반영해 실시간으로 다시 계산한다.

[6. 디자인: MongoDB LeafyGreen 디자인 시스템 (https://www.mongodb.design)]
사이트의 Foundations > Palette, Typography 페이지를 읽고 아래 기준을 적용한다.
- 라이트 모드: 배경 흰색(#FFFFFF), 보조 배경 Gray Light 3(#F9FBFA), 본문 MongoDB Black(#001E2B), 보조 글자 #3D4F58, 테두리 #E8EDEB.
- 다크 모드(사이트의 역할표 값): 기본 배경 #001E2B, 보조 배경 #112733, 본문 #E8EDEB, 보조 글자 #C1C7C6, 비활성 #889397, 테두리 #3D4F58, 링크 #0498EC.
- 색의 역할: 초록은 선택된 칩과 상단 강조선 같은 상호작용·성공(라이트 #00684A, 다크 #00ED64), 파랑은 데이터와 링크(라이트 #016BF8, 다크 #0498EC), 빨강은 경고·위험(라이트 #DB3030, 다크 #FF6960). 빨강과 초록은 색만으로 의미를 전하지 않고 글자나 태그를 함께 쓴다.
- 서체: 제목(H1, H2 수준)은 MongoDB Value Serif, 본문은 Euclid Circular A, 숫자와 코드는 Source Code Pro. 13px 미만의 작은 숫자와 단위는 Source Code Pro로 쓴다.
  Value Serif와 Euclid Circular A는 외부 웹폰트로 쓸 수 없으므로 font-family에 두 서체를 먼저 적고 Georgia, Helvetica, 한글 서체를 대체 서체로 지정한다. Source Code Pro만 Google Fonts에서 불러온다.
- 형태: 카드 모서리 12px, 필터는 알약형 칩, 4px 기준 격자에 맞춘 간격.
- 라이트·다크 모두 색은 CSS 변수로 정의하고 body 배경을 명시한다. 글자 대비는 WCAG AA(4.5:1)를 지킨다.
- 히트맵은 데이터색(파랑)의 농도로 표현하되 셀 글자가 읽히도록 농도 상한을 둔다.
- 숫자 열은 tabular-nums를 쓴다. 휴대폰 폭(약 400px)에서도 가로 스크롤 없이 보이게 한다(표만 자체 스크롤).
- 키보드로 포커스가 보이게 하고, 목록 행은 Enter로 선택할 수 있게 한다.
- 단일 HTML, 외부 데이터 요청 없음, 파일 크기 10MB 이하. 데이터는 컬럼 배열로 내장한다.

[7. 검증]
- 구문 오류가 없는지 확인한다.
- 전체 기준 수치가 아래와 같은지 확인한다: 입원 101,766건, 환자 71,518명, 재입원("<30") 11,357건(약 11.2%).
- 필터를 바꾸면 KPI, 막대, 히트맵, 목록이 함께 바뀌는지, 상세 패널에 같은 환자 기록이 나오는지 확인한다.
- 라이트·다크 모드에서 모두 글자가 읽히는지 확인한다.
```

## 알려진 한계

- 원본에 날짜가 없어서 환자의 입원 순서는 `encounter_id` 순서로 대신했습니다.
- 데이터는 1999–2008년 미국 병원 기록이라 현재 한국 진료 환경에 그대로 적용할 수 없습니다.
- 화면은 위험요인과 재입원의 연관성만 보여 주며 인과관계를 뜻하지 않습니다.
- LeafyGreen 색상 중 사이트가 텍스트로 공개한 값은 다크 모드 역할표와 링크 파랑(#016BF8)입니다. 라이트 모드의 회색·초록·빨강 등 나머지는 LeafyGreen 팔레트 기억에 의존한 값이라 공식 값과 다를 수 있습니다. 사이트 첫 화면에는 LeafyGreen이 유지보수 모드이고 새 제품은 Via를 쓰라는 안내가 있습니다.
- 위 프롬프트로 만든 결과물은 이 세션의 대시보드와 디자인 세부가 조금 다를 수 있지만, 분석 기준과 수치는 같아야 합니다.
